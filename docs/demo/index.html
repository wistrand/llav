llav in the browser

Ask yes/no, choice and rating questions about a text and get probabilities back, with the model running on your own machine. The page uses llav's prompt and readout on llama.cpp compiled to WebAssembly (wllama).

Runs locally

The model and the questions stay in this tab. Nothing you type is sent anywhere.

A 1.4 or 2.1 GB download, once

The browser keeps the last model loaded, so later visits read it from disk.

WebGPU helps

Without it the model runs on one CPU thread and a question takes tens of seconds.

Differences from the server

  
    
    
  • The model is Qwen3.5-2B, not the server's default Qwen3.5-4B: every 4B quantization is over 2 GB,
      the largest single file wllama loads. The Q8_0 file is the same one scripts/fetch-model.sh
      pins for qwen3.5-2b.
    • 
    
  • Each question reads the whole text again. The server reads a shared state once and reuses it for every
      question.
    • 
    
  • GitHub Pages cannot send the headers that allow WebAssembly threads, so without WebGPU the model runs on a
      single CPU thread.
    • 
    
  • The prompt is byte-identical to the server's. The numbers come from a different llama.cpp build, so a
      near-tie can land the other way. On 36 labelled questions with Q8_0, the page and the server chose the same
      answer 35 times; the median probability difference was 0.001 and the largest 0.11.
    • 
    
  • The candidate mass is summed over the model's 128 most likely next tokens. It flags a question none of the
      options fit, as on the server.
    • 
    
  • The text stays in the tab, but the page runs wllama from the jsDelivr CDN, pinned to one version; that
      code is trusted the way any CDN script is. A state longer than the 4,096-token context fails with
      llama.cpp's own error.
    •
